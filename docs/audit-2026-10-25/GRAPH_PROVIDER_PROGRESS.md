# Facebook/Instagram publication boundaries — 28 October 2026

Eleventh implementation increment, addressing additional A24/A10 provider-contract gaps and a credential-isolation bypass relevant to A03. These findings retain their remaining acceptance gaps; no phase is complete.

## Fixed behavior

Facebook Reels no longer finish after file-read/transfer failure or an unacknowledged transfer. Upload endpoints returned by the provider must use HTTPS on a Facebook-owned hostname, without userinfo/custom ports; redirects are rejected before credential-bearing requests can follow them elsewhere. Reels are selected by explicit aspect ratio, not by finding the word `reel` in a description.

Resumable Facebook uploads validate their session identity, initial/range offsets, exact forward-progress acknowledgements and bounded transfer budget. Failed, malformed or nonprogressing chunks stop before finish. Multipart boundaries are generated by `FormData`; a manually supplied boundary-less content type is removed. A successful finish needs a real video ID from the finish/start response. An upload-session ID is never substituted as a publication ID.

Facebook URL uploads require an HTTPS video URL and canonical returned video ID. Scheduling rejects missing video URLs or invalid/too-soon dates before dispatch, rather than submitting metadata without media. Its existing minimum scheduling window is preserved as an adapter rule; live platform compatibility is not certified here.

Instagram requires an explicit provider-accessible HTTPS `videoUrl`; it never sends a local filesystem path as `video_url`. Container IDs are validated, polling has bounded attempts/timeouts and terminal errors stop publication. An already-published container produces an uncertain-outcome hold instead of another publish attempt. A successful publication needs a canonical returned media ID. No `/p/<media-id>/` permalink is invented, since a media ID does not establish an Instagram shortcode. Optional comment failure is logged with credential redaction and does not turn an acknowledged primary publication into a failed video.

Instagram native scheduling now returns unsupported without any provider request; creating a container is not reported as a successfully scheduled publication. Managed due-time dispatch is required. Capability flags no longer advertise unimplemented carousel/story/live/thumbnail paths as available in these adapters.

Both adapters now distinguish explicit 401/403 access denial from transient or malformed credential-verification responses. Graph requests have per-request deadlines and structured status-bearing errors, and upload failures carry pre-publication `not_accepted` or post-request `unknown` dispositions. Refresh requests reject absent token responses, use bounded requests and redact token/app-secret errors; refreshed credentials are still not persisted to the vault in this increment.

## Credential isolation

The account factory already disabled global fallback by default, but these constructors independently read environment tokens and account IDs when the factory supplied an empty config. That bypass is removed. The adapters read the supplied configuration only. Explicit factory fallback can still inherit the application's configured values when enabled. Facebook's configured access-token variable is `FACEBOOK_ACCESS_TOKEN`; the constructor no longer privately reads legacy `FACEBOOK_PAGE_ACCESS_TOKEN`.

Shared error sanitization now handles encoded known-secret variants and OAuth client-secret query values as well as plain tokens. Errors/results omit raw request/config objects. Factory-level tests set global environment/config credentials while providing no connector credentials and prove that neither adapter verifies or uploads using them.

## Compatibility and remaining gaps

- **Instagram's release workflow remains blocked on artifact delivery:** the current release worker supplies local media, not an owned public delivery URL. Publishing now fails explicitly before a provider call. Adding provider-fetchable delivery must preserve owned artifact/checksum approval; accepting an arbitrary caller URL would bypass that contract. No such URL bypass was added.
- Success here is an acknowledged publication request with a canonical ID. Complete remote processing, public visibility, current Graph API version/authentication/permission compatibility and real provider behavior remain integration gates.
- Pre-publication failure can leave remote media assets/containers. Cleanup, resumable restart and distributed transactions/claims remain open. The transfer loop has a five-minute progress window, finite request count and per-request deadlines; filesystem reads/whole-file buffering remain unchanged limitations.
- Refresh-token persistence, deeper account/destination verification, provider reconciliation lookup, optional-comment recovery, and browser acceptance remain open. Native scheduling changes may require callers to use managed due-time dispatch.
- No live media upload, post, provider verification, notification, deployment or production migration occurred. Tests mock fetch/file boundaries and use temporary local stores in composed tests.
